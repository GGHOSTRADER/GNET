# Data inventory and growing the archive

[Human guide](guides/BACKTESTER_GUIDE.md) · [Agent runbook](guides/BACKTESTER_AGENT_GUIDE.md)

The selectable-source catalog is
[config/backtester.data_sources.json](../config/backtester.data_sources.json).
For exact filenames, locations, CSV/Parquet schemas and merge-to-backtester
commands, read the [file/schema contract](backtester_file_contract.md).
The [inventory command](../scripts/backtester_inventory.py) reads manifests
and Parquet footers, not millions of tick rows. It reports the asset, actual
partition coverage, row counts, resolved paths and shared session dates.
It does not merge or modify data.

These are overlapping representations of ES, **not four independent datasets
to concatenate**. The old and new sources overlap on August 13–14. The
selected splice uses old sessions through August 14 and new sessions from
August 17, with no price adjustment. It has a price-basis boundary and must

September 22 is a partial session: the new export ends on September 21 at
23:26:21 New York time. Do not treat every partition as a complete trading day.
Missing calendar dates may be weekends/holidays; this metadata catalog does
not perform an exchange-calendar completeness audit. Existing raw and prepared
archives must remain unchanged to reproduce older studies.

Only ES is registered and supported by this backtester. Adding another asset
to this catalog alone does not generalize the engine's ES tick size, contract
value or execution assumptions.

## Where data belongs

| Item | Location |
|---|---|
| Original tick exports | [historical_vp/raw](../historical_vp/raw/) — retain unchanged |
| Prepared ticks | Each catalog root: `parquet/session_date=YYYY-MM-DD/ticks.parquet` |
| Provenance / ownership | Each root's `manifest.json` |
| Bar and trade exports used by earlier studies | [MA2CrossLE inputs](../training_mlp/strategies/MA2CrossLE/inputs/) — not required to reconstruct bars from ticks |
| Bars generated by this backtester | Experiment output: `prepared/bars_<bar>.parquet` |
| Candidate signals / executed trades | `prepared/signals_<bar>.parquet` / `policies/<bar>/<phase>/<policy>/trades.parquet` |
| Experiment results and caches | `.artifacts/backtester/<unique-run-name>/` |

For new collection, use asset/type-specific folders and explicit dates:
`historical_vp/raw/ES/tick/ES_tick_1_<first-date>_to_<last-date>_export_<stamp>.txt`
or `historical_vp/raw/ES/volume/ES_volume_1_<first-date>_to_<last-date>_export_<stamp>.txt`.
The volume-bar importer/grouping command is documented in
[source-bar aggregation](source_bar_aggregation.md); it is distinct from the
individual-tick preparation command below.
This is a naming convention for future files; existing files were not moved.
Use explicit file paths with the preparation tool for subfolders. Record
symbol/contract, export vintage, timezone and session convention in provenance;
the filename alone is not enough to establish compatibility.

## Inspect and select an archive

```powershell
Set-Location 'C:\Users\g_med\python_new\GNET'
.\.venv\Scripts\python.exe -m scripts.backtester_inventory data --asset ES
.\.venv\Scripts\python.exe -m scripts.backtester_inventory data --dataset es_spliced_20260921 --json
```

The JSON includes every partition path and row count, plus manifest SHA-256.
Without `--dataset`, the report also lists shared dates across registered
archives. Shared dates are a warning, not proof of identical tick sequences.

Copy the resolved `tick_root` into your experiment JSON. Choose inclusive
`start_session` and `end_session` and a fresh `output`. Catalog IDs are discovery
labels; `backtester.run` currently takes a path, not a dataset ID. Relative
paths in experiment JSON and in the catalog resolve against their respective
JSON file's directory.

## How the history grows without breaking old experiments

Keep the raw export and prepare each new delivery into a **new** directory.
The existing [preparation tool](../training_mlp/prepare_historical_vp.py)
accepts explicit inputs and output paths; inspect its options with:

```powershell
.\.venv\Scripts\python.exe -m training_mlp.prepare_historical_vp --help
```

Template for a future file (replace the angle-bracket values; do not run
literally):

```powershell
.\.venv\Scripts\python.exe -m training_mlp.prepare_historical_vp 'historical_vp/raw/ES/tick/<new-export>.txt' --symbol '@ES' --timezone America/New_York --output 'historical_vp/<new-prepared-directory>' --workers 2
```

Then audit any overlap against the existing archive: tick order, timestamps,
prices, volume, symbol and adjustment vintage. A newer continuous-contract
export may revise historical prices. Do not automatically enable
`--allow-conflicting-overlaps`, add both copies, or interpret a price adjustment
as a tradable move.

After resolving ownership and rollover boundaries, build a new versioned
consolidated snapshot with one owner per session and a manifest explaining the
choices. The current [splice implementation](../training_mlp/splice_historical_vintages.py)
documents the September handoff and accepts explicit sources/cutoff for other
paired deliveries, but is **not a generic tick-only append service**.
An automatic arbitrary-date archive updater is not implemented yet. The
catalog does not pretend to provide one.

Register the new snapshot in the catalog with a unique ID, asset, symbol,
timezone, root, status and notes. Rerun the inventory command and select that
new root in a new experiment. Older experiments retain their old source roots.
This gives an ever-growing collection of reproducible versions rather than
silently changing the data beneath existing studies.

See [historical data preparation](../historical_vp/README.md) for the existing
archive pipeline and [technical preparation reference](historical_vp_preparation.md)
for validation and overlap handling.
